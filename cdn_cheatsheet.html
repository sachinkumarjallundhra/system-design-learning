📦 CDN (Content Delivery Network) Cheatsheet

✅ What is a CDN?

A CDN is a geographically distributed network of servers (edge servers) that deliver content to users based on their geographic location. It helps reduce latency, increase speed, and offload the origin server.

🌟 Goals of a CDN

  • Reduce latency
  • Improve performance
  • Increase availability and redundancy
  • Handle traffic spikes efficiently
  • Provide security features (DDoS protection, HTTPS termination)

🧱 Core Components

ComponentDescription
ClientEnd-user making the request
Edge ServerCaches and serves content near the client
PoPPoint of Presence (location of edge server)
Origin ServerYour backend/web server
CDN ProviderCloudflare, Akamai, Fastly, AWS CloudFront

⚙️ How It Works

  1. Client requests a resource (e.g., image.js)
  2. DNS routes request to nearest PoP
  3. Edge server checks cache:
    • Hit → Serve cached content
    • Miss → Fetch from origin, cache it, serve to client

🧠 Key Concepts

📌 Cache-Control Headers

  • Cache-Control: public, max-age=3600
  • ETag, Last-Modified: validators for cache freshness

♻️ Cache Invalidation

  • TTL expiry (time-based)
  • Manual purge (API/UI)
  • URL versioning (e.g., /v2/logo.png)

🛡️ CDN Security

  • DDoS mitigation
  • TLS/SSL termination
  • WAF (Web Application Firewall)

📦 Use Cases

  • Static file delivery (images, JS, CSS)
  • Video streaming
  • Software downloads
  • API acceleration (global users)

🧪 CDN in Interviews

  • “How does your system handle global scale?”
  • “How do you reduce latency and improve reliability?”
  • Discuss TTL, cache invalidation, fallback to origin
  • Mention integration with Load Balancer, WAF

🔗 Real-World CDN Providers

  • Cloudflare – performance + security
  • Akamai – enterprise-grade
  • Fastly – developer-friendly, real-time purging
  • Amazon CloudFront – AWS-native
